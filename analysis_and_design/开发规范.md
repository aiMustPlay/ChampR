# ChampR 开发规范

## 1. 所有测试/验证命令必须设置超时

为避免命令无限期挂起，所有测试、构建、服务启动、网络请求等验证命令都必须带明确的超时限制。禁止直接运行可能长时间无输出的命令而不加超时。

### 通用原则

- 优先使用命令本身提供的超时参数。
- 命令没有超时参数时，使用 PowerShell 的 `Start-Job` + `Wait-Job -Timeout` 包装。
- 通过 `yield_time_ms` 执行命令时，控制在合理范围内（建议 30s），超时后转为轮询而不是继续阻塞等待。

### PowerShell 超时包装示例

```powershell
function Invoke-WithTimeout {
    param(
        [Parameter(Mandatory = $true)]
        [int]$Seconds,

        [Parameter(Mandatory = $true)]
        [scriptblock]$ScriptBlock
    )

    $job = Start-Job -ScriptBlock $ScriptBlock
    try {
        if (Wait-Job -Job $job -Timeout $Seconds) {
            Receive-Job -Job $job
        }
        else {
            Stop-Job -Job $job
            throw "命令在 $Seconds 秒内未完成，已强制终止"
        }
    }
    finally {
        Remove-Job -Job $job -Force -ErrorAction SilentlyContinue
    }
}
```

### 常用命令超时建议

| 场景 | 建议做法 |
| --- | --- |
| `cargo test` / `cargo run` | 用 `Invoke-WithTimeout` 包装，或使用支持 `--timeout` 的工具 |
| `docker compose build/up` | 设置 `yield_time_ms`，轮询时也设定最大等待时间，超时中断 |
| `pnpm install` / `playwright install` | 设置命令自身的网络超时，并用 `Invoke-WithTimeout` 限制总时长 |
| `curl` / `Invoke-WebRequest` | `curl --max-time <秒>`；`Invoke-WebRequest -TimeoutSec <秒>` |

## 2. 网络相关命令

- 需要外网的命令优先使用国内镜像或已配置的代理。
- 下载类命令必须可中断、可重试，不得无限等待。

## 3. 命令执行记录

- 每次长时间命令执行时，记录开始时间、超时上限和最终结果，便于排查是否超时。
